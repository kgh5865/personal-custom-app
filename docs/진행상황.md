### OAuth 채팅 실패 해결

OAuth 연결 후 모든 전송이 실패하던 문제. 원인은 두 개였다.

1. **Codex `version` 헤더 게이팅** — 박혀 있던 `0.20.0`이 너무 낮아 모델과 무관하게
   전부 400. 실기기 토큰으로 확인: `0.20 / 0.30 / 0.45 / 0.60 / 0.99` → 400,
   `0.146.1`(npm 최신) → `gpt-5.5`, `gpt-5.6-{sol,terra,luna}` 전부 200.
2. **SSE 파서** — Codex backend는 `response.completed`의 `output`을 빈 배열로 보내고
   실제 결과는 `response.output_item.done`으로 흘린다. 파서가 `completed`만 봐서
   200을 받아도 텍스트·툴콜이 항상 비어 있었다.

`files/domains/memo/{meta.json,index.html,style.css,script.js}` 생성 확인.

#### 기기 검증 중 잡은 마이그레이션 버그

1차 설치에서 **마이그레이션이 조용히 전부 건너뛰어졌다.** 암호화 저장소에는 키셋만
생기고 데이터는 하나도 안 옮겨졌으며, 앱은 로그인이 풀려 `.env` 게이트웨이로 폴백했다.
에러 로그조차 없었다.

원인: 네이티브 `SecureStorage.get`이 값이 없을 때 `null`이 아니라 **`undefined`** 를
돌려준다 — Java `JSObject.put(key, null)`이 키를 아예 넣지 않기 때문이다. 그런데
`migratePlaintext`가 `existing !== null`로 검사해서 `undefined !== null`이 참이 되어
"이미 있음"으로 오판, 모든 키를 건너뛰었다.

수정: 백엔드에서 `value ?? null`로 정규화하고, 검사도 nullish(`!= null`)로 바꿨다.
회귀 테스트는 **네이티브처럼 undefined를 돌려주는 백엔드**로 재현한다 — 기존 테스트가
`null`을 돌려주는 fake만 썼기 때문에 이 버그를 못 잡았다.

### P0 마무리 — 401 처리 · 챗 재시도

**401 응답 처리** ([openai.ts](../src/lib/openai.ts), [oauth.ts](../src/lib/oauth.ts))
기존에는 만료시간 기반 선제 refresh 뿐이라, 서버가 실제로 401 을 주면 그냥
`openai 401: ...` 문구만 떴다. 이제 401 이면 `forceRefresh()` 로 1회 갱신하고
**헤더를 새로 만들어** 딱 한 번 재시도한다(무한 루프 없음). 갱신까지 실패하면
토큰을 폐기(`logout()`)하고 `AuthExpiredError` 를 던진다. 챗은 `isAuthExpired()` 로
이를 구분해 재시도 대신 **"설정에서 다시 로그인"** 링크를 띄운다.

**챗 실패 복구** ([Chat.svelte](../src/routes/Chat.svelte))
기존 `send()` 는 API 호출 **전에** 사용자 메시지를 저장했다. 그래서 실패 후
사용자가 같은 말을 다시 치면 히스토리에 중복으로 쌓였다 — 실제로 디버깅 기간에
"안녕" 말풍선이 6개 쌓여 있었다.
`send()`(저장 + 실행)와 `retry()`(실행만)로 분리해, 재시도는 **이미 저장된**
메시지를 재사용한다. 실패해도 사용자가 친 문장은 대화에 남고, 에러 카드에
재시도 버튼이 붙는다.

**덤으로 잡은 실제 버그**: `onMount` 가 async 라 반환한 cleanup 함수를 Svelte 가
무시하고 있었다 — `visualViewport` resize 리스너가 해제되지 않고 누수됐다.
등록/해제를 `onMount`/`onDestroy` 로 분리했다. (`svelte-check` 15 → 14건)

**4.4 도메인 화면 자동 갱신은 취소했다.** 챗과 도메인은 별개 라우트라 도메인을
보는 중에는 채팅을 할 수 없고, 진입할 때마다 `$: if (params?.name) load()` 로
디스크에서 새로 읽는다. 실기기에서 patch 직후 도메인에 들어가 변경이 즉시 보이는
것을 확인했다. 현재 UI 에서는 재현되지 않는 문제라 구현하지 않는다.
챗·도메인을 동시에 띄우는 UI 가 생기면 그때 다시 본다.

실기기 검증: 네트워크를 끊고 전송 → 에러 카드 + 재시도 버튼, 복구 후 재시도 →
성공하고 **메시지 중복 없음**(DB 에서 해당 문구 1건 유지, assistant 응답만 +1).

### iframe 격리 검증 — Phase 1 DoD 종료, 단 한계 하나 발견

깨진 도메인(`broken`)을 기기에 직접 심어 결정적으로 확인했다. 닫히지 않은 태그,
문법이 깨진 CSS, 즉시 throw 하는 JS 를 넣었다.

**통과**: 화면은 브라우저가 복구해 렌더했고, JS 는 `null.boom()` 에서 터졌는데
로그가 `File: about:srcdoc - Uncaught TypeError` 로 남았다 — iframe 안에 갇혔다는
증거다. 호스트 헤더·하단 탭·챗·설정 전부 정상 동작했다. 깨진 CSS 도 호스트로
새지 않았다. (덤으로 `meta.json` 만 심었는데 홈에 떴다 — self-heal 동작 확인)

**한계**: `while(true){}` 를 넣으면 **WebView 전체가 얼어붙는다.** 하단 탭조차
반응하지 않고, 앱을 강제 종료해야 한다. `sandbox="allow-scripts"` 는 origin 과
DOM 은 격리하지만 **CPU 는 격리하지 않는다** — iframe 이 렌더러 메인 스레드를
공유한다. 설계서 5.3 의 "GPT 가 짠 깨진 JS 가 앱 전체를 멈추지 않게 함" 은
무한 루프에 대해서는 성립하지 않는다.

제대로 막으려면 도메인을 별도 프로세스/WebView 로 띄워야 하는데, 개인용 앱에
비해 과하다. 대신 **진짜 위험한 부분만 막았다**: 얼어붙은 도메인은 삭제 버튼이
그 얼어붙은 화면에만 있어서 **영영 지울 수 없었다**. 홈 카드를 길게 누르면
삭제되도록 해서 탈출구를 만들었다([Home.svelte](../src/routes/Home.svelte)).
무한 루프를 심은 도메인을 열지 않고 홈에서 삭제하는 것까지 기기에서 확인했다.

### P1 — tool_call 인자 검증 · 테스트 격리

**tool_call 인자 검증** ([registry.ts](../src/lib/gpt/registry.ts))
`invoke()` 가 등록된 함수인지만 보고 스키마 검증 없이 실행하고 있었다.
`delete_domain` 에 `domain` 이 undefined 로 오면 경로가 `/domains/undefined` 가
되는 식의 문제가 그대로 통과했다. 이제 실행 **전에** `TOOL_DEFS` 스키마로
검증하고, 문제를 전부 모아 GPT 에게 돌려준다. bridge 루프가 그 결과를 다시
넣어주므로 모델이 자가 수정한다.
- 검증 기준은 `tools.ts` 의 `TOOL_DEFS` **단일 출처** — 스키마가 바뀌면 검증도 따라간다
- 여분 필드는 허용한다(모델이 종종 덧붙인다. 이걸로 실행을 막으면 손해다)
- 예: `patch_screen: 필수 인자 'search' 가 없습니다`,
  `create_domain: 'name' 은 string 이어야 하는데 number 를 받았습니다`

**테스트 격리** ([vitest.config.ts](../vitest.config.ts))
`tests/oauth.test.ts` 1건이 계속 실패하고 있었다. 원인은 테스트가 레포 루트의
`.env` 를 읽어 `import.meta.env.VITE_OPENCLAW_URL` 이 채워지고, 그 탓에
`getAuthMode()` 가 null 대신 게이트웨이를 돌려준 것이다 — 개발자 로컬 설정에 따라
결과가 달라지는 상태였다. `envDir` 를 `.env` 가 없는 디렉터리로 돌려 `VITE_*` 를
비웠고, 가정이 깨지면 바로 드러나도록 `sanity.test.ts` 에 가드를 넣었다.

**전체 스위트가 처음으로 완전히 초록이 됐다 — 138/138.**

### P2 — 온보딩 · 휴지통 복원 · 타입 정리

**첫 실행 온보딩** ([Onboarding.svelte](../src/routes/Onboarding.svelte), [App.svelte](../src/App.svelte))
OAuth 로그인 UI 를 온보딩에 복제하지 않았다. 이미 Settings 에 있고 복제하면 두 곳을
유지해야 한다. 대신 **체크리스트 + 기존 화면 링크** 방식으로 만들었다 — 코드가 훨씬
적고 유지보수 지점이 하나다. AI 연동·프로필 입력 두 항목의 완료 여부를 실시간 표시하고,
다 안 채워도 "시작하기" 로 넘어갈 수 있다(강제하지 않는다).
진입 조건은 `!done && authMode === null` — **이미 로그인한 사용자에겐 뜨지 않는다.**

리뷰에서 고친 것: 판정이 실패하면 `ready` 가 영영 false 로 남아 **앱 전체가 빈 화면**이
되는 구조였다. 시크릿 저장소가 네이티브 Keystore 를 타게 되면서 실패 경로가 실재한다 —
예전엔 챗만 깨질 상황이 이제 셸을 죽인다. `try/finally` 로 어떤 경우에도 셸은 뜨게 했다.

**휴지통 복원** ([domains.ts](../src/lib/domains.ts), [Settings.svelte](../src/routes/Settings.svelte))
`delete_domain` 이 휴지통으로 옮기기만 하고 되살릴 방법이 없어 파일만 쌓이고 있었다.
`listTrash()` / `restoreFromTrash()` / `purgeTrash()` 를 추가하고 설정에 휴지통 섹션을
붙였다(복원 · 영구삭제 · 비우기). 복원 시 이름이 충돌하면 덮어쓰지 않고
`<name>-restored`, `-restored-2` … 로 피한다.

리뷰에서 잡은 버그: `fs.copy` 는 Capacitor `Filesystem.copy` 직결이라 **대상 디렉터리를
만들어주지 않는데**, 복원이 폴더를 만들기 전에 복사부터 하고 있었다. 실기기에서만
터지는 버그인데 **테스트의 fake fs 가 부모 디렉터리를 자동 생성해서 통과시켰다.**
코드에 `mkdir` 을 넣고, **fake fs 도 실제와 같이 엄격하게 바꿔** 이 부류를 앞으로
잡도록 했다(수정 제거 시 복원 테스트 3개가 실패하는 것을 확인).

**타입 정리**: `svelte-check` **14건 → 0건**.

실기기 검증: 휴지통에서 `memo` 복원 → 파일 4개 + history 스냅샷 복귀,
patch 했던 배경색 보존, `domain_meta` 반영, 휴지통에서 제거 확인.
로그인 상태라 온보딩이 뜨지 않는 것도 확인.

## 5. AI 채팅 기반 기능 설계 (신규 · 착수 전)

앱 안에서 GPT를 쓰는 이상, 일반 AI 채팅이 갖춘 기본기가 있어야 한다.
현재는 하나도 없다 — [bridge.ts:31](../src/lib/gpt/bridge.ts:31)이 매 요청마다
**전체 대화 이력을 그대로 다시 보낸다**. 대화가 길어질수록 요청당 비용이 선형으로
늘고, 누적으로는 제곱으로 늘어난다.

### 5.1 비용 구조부터

설계 판단의 근거가 되므로 먼저 못박아둔다.

- **출력 토큰이 입력보다 훨씬 비싸다** (모델별로 대략 4~5배).
- 따라서 절감 효과 순서는:
  1. **모델이 뱉는 양을 줄인다** ← 가장 큰 레버. 전체 파일 재작성 → 부분 패치
  2. 모델에 넣는 양을 줄인다 ← 압축, 범위 읽기
  3. 추론 강도 조절
- 이 순서가 5.2~5.4와 6장의 우선순위를 결정한다.

### 5.2 컨텍스트 압축 (compact)

**현재**: [chat.ts](../src/stores/chat.ts)가 최근 200개를 불러오고 bridge가 전부 전송.
Codex 컨텍스트가 1.05M이라 당장 터지진 않지만, 매 턴 값을 다시 낸다.

**설계**:
- 추정 입력 토큰이 임계값(예: 30k)을 넘거나 턴 수가 N을 넘으면 압축을 건다.
- 최근 K턴은 원문 유지, 그 이전 구간을 모델에게 요약시켜 블록 1개로 접는다.
- 요약 결과는 저장해 재계산하지 않는다.

```sql
CREATE TABLE chat_summary (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  upto_message_id INTEGER NOT NULL,   -- 이 id 이하가 요약에 포함됨
  content         TEXT    NOT NULL,
  created_at      INTEGER NOT NULL
);
```

- 이후 요청 = 시스템 프롬프트 + 최신 요약 + `upto_message_id` 이후 원문.
- UI: 챗에 "이전 대화 요약됨" 구분선, 설정에 수동 압축 버튼.
- 주의: 압축 자체가 1회 비용이다. 임계값을 너무 낮게 잡으면 손해다.

### 5.3 메모리

**프로필과 역할을 나눈다.**

| | `user_profile` | `memories` |
|---|---|---|
| 성격 | 정형, 고정 스키마 | 비정형, 자유 |
| 예 | 출생연도, 거주지, 직업, 소득 | "커피 안 마심", "신혼부부 특공 노리는 중" |
| 갱신 | 프로필 화면 + `update_user_profile` | 대화 중 GPT가 `remember` 호출 |

```sql
CREATE TABLE memories (
  key        TEXT PRIMARY KEY,
  value      TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

**도구**: `remember(key, value)` / `recall(query?)` / `forget(key)`

**주입 방식**: 매 요청 시스템 프롬프트에 전체 메모리를 넣는다. 단 상한(예: 50개 /
2000자)을 두고, 넘으면 주입은 최근 것만 하고 나머지는 `recall`로 꺼내게 한다.

**포착 방식**: 별도 추출 호출을 붙이면 매 턴 비용이 2배가 된다. 대신 시스템
프롬프트에 "기억해둘 만한 사실을 알게 되면 `remember`를 호출하라"고 지시해
모델이 판단하게 한다. 싸고 충분하다.

**UI**: 설정에 메모리 목록 조회·삭제. 사용자가 뭘 기억당하고 있는지 볼 수 있어야 한다.

### 5.4 토큰 절약

| 항목 | 현재 | 개선 |
|---|---|---|
| `read_screen` | 파일 3개 전문 반환 | `read_screen(domain, file?, from?, to?)` 범위 지정. 기본은 구조 개요만 |
| 도구 결과 크기 | 무제한 | 상한 두고 초과분 `…N자 생략` 표시 |
| 도구 스키마 | 9개 전부 매 요청 전송 | 고정 비용. 지금 규모에선 방치 |
| 사용량 가시성 | 없음 | SSE `response.completed`의 `usage`를 파싱해 설정에 누적 표시 |
| 추론 강도 | 수동 설정 | 유지 (이미 있음) |

사용량 표시를 먼저 붙이는 걸 권한다. **측정 없이 최적화하면 헛돈다.**

## 6. 도메인 버전 관리 · 최소 수정 설계 (신규 · 착수 전)

AI가 홈 UI를 계속 고쳐나갈 것이므로, 두 가지가 필요하다:
**뭘 바꿨는지 추적**하고, **원하는 부분만 최소 비용으로 고치는 것**.

### 6.1 지금의 문제

- [domains.ts:136](../src/lib/domains.ts:136) `update()`는 파일을 **통째로 다시 쓴다**.
  버튼 색 하나 바꾸려고 HTML 전체를 모델이 재출력한다 — 5.1 기준 가장 비싼 짓이다.
- 이력이 `history/<timestamp>/` 전체 스냅샷뿐이라 **왜 바뀌었는지 기록이 없다**.
  `revert(steps)`로 되돌릴 수는 있는데 사용자는 뭘 되돌리는지 모른다.
- 전체 재작성은 비용 문제만이 아니다. 모델이 "안 건드려야 할 부분"까지 매번 다시
  써서 **의도치 않은 변경(회귀)이 섞여 들어간다.**

### 6.2 최소 수정 — 4단 설계

**① `patch_screen` 우선 사용** (이번에 구현)
`patch_screen(domain, file, search, replace)`. 바뀌는 부분만 출력하므로 출력 토큰이
수십 분의 일로 줄고, 건드리지 않은 영역은 물리적으로 보존된다.
→ 도구 description과 시스템 프롬프트 양쪽에 "작은 수정에는 `update_screen` 대신
이걸 쓰라"고 명시한다.

**② 섹션 앵커 규약**
`create_domain`이 만드는 기본 템플릿에 주석 앵커를 심는다:

```html
<!-- @section:header -->
...
<!-- /@section:header -->
```

시스템 프롬프트로 "새 마크업을 만들 때도 섹션 앵커를 유지하라"고 지시하면,
patch의 `search` 문자열이 **유일하고 안정적**이 된다. 앵커 없이 임의 문자열을
찾게 하면 중복 매칭으로 실패율이 올라간다.

**③ 실패 시 자가 수정**
`search`를 못 찾거나 2회 이상 찾으면 구체적 에러를 GPT에게 되돌려준다.
[bridge.ts:57](../src/lib/gpt/bridge.ts:57)이 이미 도구 결과를 모델에게 다시 넣으므로
별도 장치 없이 자동 재시도된다. (이번 구현에 포함)

**④ 중복 읽기 방지**
같은 대화에서 이미 읽은 파일을 다시 `read_screen` 하지 않도록 시스템 프롬프트에
명시. 지금은 모델이 습관적으로 매번 읽는다.

### 6.3 버전 관리

**스냅샷 유지, 메타데이터 추가.** diff 저장으로 바꾸는 건 과설계다 — 도메인 20개
스냅샷은 용량이 문제되지 않고, 스냅샷은 복원이 확실하다.

각 history 엔트리에 `change.json`을 함께 저장한다:

```json
{
  "at": 1786024409000,
  "tool": "patch_screen",
  "reason": "헤더 배경을 어두운 색으로",
  "files": ["html"]
}
```

- `reason`은 `update_screen` / `patch_screen` 도구 스키마에 **필수 인자**로 추가해
  모델이 매번 한 줄 요약을 남기게 한다.
- [Domain.svelte](../src/routes/Domain.svelte)에 버전 목록 UI: 언제 · 뭘 · 왜 바꿨는지.
  현재는 "되돌리기" 버튼 하나로 직전 버전만 간다.
- 특정 버전 지정 복원. `revert(steps)`는 유지하되 UI는 목록에서 고르게.

### 6.4 작업 순서 제안

1. `patch_screen` (①) — 이번 작업에 포함
2. `reason` 인자 + `change.json` (6.3) — 작고 효과 큼
3. 버전 목록 UI
4. 섹션 앵커 규약 (②) + 시스템 프롬프트 정비 (④)
5. `read_screen` 범위 지정 (5.4)
